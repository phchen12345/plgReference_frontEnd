台灣籃球資料站前端架構圖

這張圖以目前專案為基礎整理，重點放在面試常問的分層、資料流、狀態管理、快取策略與頁面組成。

Next.js App Router React 19 Chakra UI TanStack Query Zustand TypeScript

1. 進入頁面

使用者開啟首頁或點擊已完賽卡片。Next App Router 依 route 載入 app/home/page.tsx 或 app/games/[gameId]/page.tsx。

2. Server 先取資料

首頁用 getSchedule 取賽程；賽事頁用 getGameBoxscore 取 boxscore。共用 requestJson 處理 API response。

3. Client 接手互動

收藏球隊、篩選、分頁、聊天室與深色模式都在 client component 運作。首頁已完賽分頁透過 TanStack Query 做快取和重新抓取。

4. UI 組件呈現

Chakra UI 負責版面與樣式，Recharts / Chakra Charts 顯示統計圖， Zustand 保存使用者偏好到 localStorage。

面試可以這樣講

  • 專案採用 feature-based structure，首頁和賽事頁各自有 api、types、components。
  • 頁面資料優先在 Server Component 抓，降低首屏 loading 與 client bundle 壓力。
  • 需要互動的部分再切成 Client Component，例如篩選、分頁、聊天和主題切換。

資料流重點

  • NEXT_PUBLIC_API_BASE_URL 是後端入口。
  • /api/schedule 提供賽程和分頁資料。
  • /api/games/:gameId/boxscore 提供單場比賽統計。
  • /ws/chat 是聊天室 WebSocket。

可優化方向

  • 把中文亂碼修正，避免 UI 與註解維護困難。
  • 讓 API base URL 缺失時在 server/client 都有一致錯誤訊息。
  • 針對 schedule filter 和 boxscore table 補測試，保障面試展示穩定度。

專案檔案對照

架構入口：app/layout.tsx、app/providers.tsx。 首頁：app/home/page.tsx、features/home。 賽事頁：app/games/[gameId]/page.tsx、features/games。 API 共用層：lib/api/client.ts、lib/api/response.ts。 使用者偏好：stores/useFavoriteTeamsStore.ts、 stores/useColorModeStore.ts。 TanStack Query 的主要使用點在首頁 features/home/components/FinishedGamesSection.tsx。

使用方式：直接用瀏覽器開啟這個 HTML。面試時可先講分層，再講首頁資料流，最後補狀態管理與可優化方向。
